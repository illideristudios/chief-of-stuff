# Issue #378: count every one-shot toward the workspace cap

This is an implementation plan for `github:illideristudios/chief-of-stuff#378`.
The plan stage changes no runtime behavior.

## Confirmed cause

`spawn_session.main()` accepts an absolute `--cwd` and delegates one-shots to
`one_shot.run()`. `one_shot.slot()` locks the configured Worktrees directory,
counts `process_status.running_trees(trees)`, and writes `cwd / PIDFILE`.
`process_status.pidfile_runs()` discovers only `trees/*/.chief-of-stuff/one-shot.pid`.
An external cwd, the workspace root, or a nested directory can therefore hold a
live claim that the next launch never counts. The lock serializes the checks but
does not fix this discovery gap.

A temporary-directory probe against the current code, using the current process
as the live launcher, produced:

```text
external_pidfile_exists=True
counted_running_workers=0
second_claim_admitted_at_cap_1=True
```

Relevant existing coverage is in `evals/test_one_shot.py`: `RunTest` covers cap
refusals and worker PID handoff, and `ConcurrentLaunchTest` exercises simultaneous
slot claims. All those slot claimants currently live immediately below `trees`.

## Required behavior

- One workspace's cap includes every active one-shot launched for that workspace,
  regardless of cwd location or runtime. Interactive sessions do not consume it.
- A run counts once, including during launch preparation and reconciliation. A
  worker surviving its launcher still counts while its worker PID is alive.
- Admission and publication of a new claim occur inside the same shared lock.
  At cap, refuse before starting a worker or changing its tracker row.
- Normal completion and launch failure release the claim. Stale records whose
  launcher and worker are both dead do not hold slots indefinitely.
- An absent cap remains unlimited, with claims still recorded so setting a cap
  later does not hide already running workers.
- `--dry-run` and `--check` retain their existing preview/validation semantics and
  do not reserve slots.

## Proposed implementation

### 1. Add workspace-owned discovery, retain the tree PID protocol

Introduce a small shared module, for example `scripts/one_shot_registry.py`, for
workspace claim storage and enumeration. Use a workspace-local directory such as
`root/.chief-of-stuff/one-shot-runs/`, separate from interactive `sessions/` and
result `reports/`. No new dependency is needed.

Each claim records a schema version, unique run token, canonical absolute cwd,
task item, and launcher PID. Its filename is generated by the launcher, never
derived from raw task text. The existing cwd-local `<pid> <task>` PID file remains
the worker PID source; `_run_worker()` already replaces the launcher's PID there
after `Popen`. This avoids maintaining two independently updated worker PID files
and preserves `_clear_stale_dispatch()` and stopped-run evidence.

Provide a workspace-aware iterator of run records. Discover the union of registry
claims and existing immediate-child PID files, canonicalize paths, and deduplicate
by cwd so one run discovered both ways counts once. Keep legacy in-tree discovery
for runs started before the change. Count a registry claim when its launcher is
alive OR its matching cwd PID file names a live process. Require the PID file's
task to match the registered task before using it as the surviving worker's
evidence. Preserve raw task strings internally for tracker joins; sanitize them
only at existing display boundaries.

Keep bounded, nonblocking, regular-file-only, no-follow reads for both registry
records and cwd PID files, using existing safe file helpers. Validate JSON shape,
positive ASCII PID values, absolute cwd, and field sizes before using a record.
Do not execute anything found in a record. A malformed registry entry is an
accounting error: capped admission must refuse with a fixed diagnostic rather
than silently treating it as a free slot. Diagnostic readers can warn and omit
the invalid entry. Keep the current treatment of malformed legacy PID files.

### 2. Claim and release under one lock

Pass the workspace root into `slot()` and use the workspace-aware iterator for
its count. Retain the existing lock on the configured Worktrees directory so
updated launchers still serialize with older launchers. Do not add a second lock
with an ambiguous ordering.

Inside that lock: read the existing claims, reject an already active canonical
cwd, check the cap, atomically publish the registry record and write the local
launcher PID file before yielding. Roll back any partially written claim on
failure. Publish the record with the existing `atomic_write` helper so readers
never see partial JSON. Register every real launch, including unlimited mode.

On exit, reacquire the same lock and release only this token's record and local
PID file. The token check prevents an old context's cleanup from removing a newer
run's claim. A process crash leaves its record available for liveness checks and
adoption. Dead records do not consume slots, but keep their external cwd discoverable
until adoption/reconciliation completes; only then remove the matching record under
the lock. Do not remove local dispatch, result, or dead PID evidence needed by
adoption. Defer general abandoned-record garbage collection rather than erasing
the only pointer to an unreconciled external run.

Holding a live launcher claim through reconciliation and the timeout retry gap
prevents the temporary absence of a live worker PID from granting an extra slot.
Retain the existing worker-PID publication immediately after spawn. Its existing
spawn-to-PID-publication crash window is a residual risk, not solved by cwd
discovery; document it rather than claiming crash-proof process supervision.

### 3. Use the same discovery for operator diagnostics

Add a workspace-aware entry point rather than inferring a root from `trees.parent`
(Worktrees can be configured elsewhere). Preserve legacy trees-only helpers for
callers that intentionally inspect a directory. Update `processes --root` to use
workspace discovery so the refusal's suggested command lists external workers.
Keep its TOON schema, tracker-backed task filtering, and tree-name sanitization.

Audit `board_sources`, `tree_claims` (including its `audit_tasks` caller), and
`one_shot.adopt`, which also use these helpers. Use workspace discovery in the
root-aware live-run readers to keep visibility and tree protection consistent.
Preserve the trees-only adoption behavior and its evidence. External adoption is
not an acceptance requirement here: `_running_row()` currently matches a basename
although `_tree_note()` writes an absolute external path, and `launcher_copy()`
keys reports by basename. Fixing those ownership/report identities is a separate
follow-up; do not silently broaden this cap fix into a reconciliation redesign.
Keep unreconciled external registry records discoverable for that follow-up.

Clarify in `README.md` that `max_concurrency` is per workspace and independent of
the worker cwd. No settings or CLI flag changes are required.

## Test-first sequence

1. **Red regression:** add a real, held external slot with cap 1, then attempt an
   internal launch for a different, nonoverlapping task. Assert refusal, the
   count/cap diagnostic, unchanged tracker, and no second worker invocation.
   Also test external-to-external and internal-to-external admission. Use fake
   agents and temporary directories, with no actual runtime or forge calls.
2. **Discovery and isolation:** cover workspace-root and nested cwds; canonical
   symlink aliases; two external cwds sharing a basename; legacy plus registered
   discovery counting once; multiple runs with the same PID in test fixtures
   still counting separately by cwd; a separate workspace not consuming this
   workspace's cap; and interactive registrations being excluded.
3. **Lifecycle:** cover success, `_launch` exception, PID write/publication error,
   dead launcher/dead worker, dead launcher/live worker, live launcher during
   reconciliation and timeout retry, and token-checked cleanup. Assert both
   registry state and admission behavior. Use controlled subprocesses for
   liveness, with cleanup registered so tests leave no workers behind.
4. **Concurrency:** adapt `_slot_child` and the existing twelve-claimant test to
   mix internal, nested, and external cwds. Keep the count-to-publication delay
   and barriers; cap 3 must admit exactly three simultaneous claims. Add an
   external-only variant. Barriers, not timing guesses, hold successful claims
   until all refusals have answered.
5. **Reader safety and diagnostics:** test malformed/oversized records, symlinks,
   FIFOs, invalid PIDs, mismatched PID-file tasks, and nonprintable task/path
   content. Assert prompt reads, fixed cap errors without raw record text, and
   existing task filtering in `processes`. Test external active-run visibility,
   retention of dead external records without consuming slots, and unchanged
   legacy adoption behavior.
6. **Compatibility:** retain existing cap refusal text, unset-cap behavior,
   preview behavior, stopped-dispatch recovery, timeout, and adoption coverage.
   Run the relevant suites, then the repository's complete Python suite:

   ```text
   python3 -m unittest evals.test_one_shot evals.test_process_status evals.test_spawn_session evals.test_settings
   python3 -m unittest discover -s evals -p 'test_*.py'
   ```

Suggested implementation commits: first the failing regressions plus the
registry/admission fix that makes them pass; then shared reader integration and
its tests/documentation. Commit each coherent change without merging.

## Risks and limits

- **Upgrade with external workers already running:** their old launcher never
  recorded a workspace claim, so they cannot be discovered reliably by scanning
  Worktrees. Drain old one-shots before enabling the updated launcher. Legacy
  in-tree workers remain discoverable; mixed-version external launches can still
  escape the cap. Do not scan the entire filesystem or global process commands.
- **PID reuse:** the existing PID protocol can mistake a reused PID for a live
  worker. This plan preserves that limitation; process-start identity is a
  separate hardening task.
- **Untrusted metadata:** neither registry corruption nor worker-controlled text
  should grant a capped slot or reach diagnostics verbatim. A workspace path may
  also be writable by a worker; this remains cooperative accounting rather than
  an enforcement boundary against a malicious worker.
- **Lifecycle races:** keep the registry claim until reconciliation completes;
  test cleanup under the same lock and preserve evidence after launcher death.
  Do not replace directory-lock inodes while launchers are active.
- **Reader compatibility:** avoid globally changing a trees-only helper's
  argument meaning. Explicit workspace-aware APIs keep configured external
  Worktrees locations and existing fixtures unambiguous.

## Acceptance

The original cap-1 probe must refuse its second claim after implementation.
Mixed-location parallel claims must never exceed the configured cap, terminal
runs must free their claims, and `processes --root` must account for the same
external runs as admission. All regression and existing tests must pass.
